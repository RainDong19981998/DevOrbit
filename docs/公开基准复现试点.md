# 公开基准复现试点

## 结论与边界

DevOrbit V0.8.0 已冻结并真实计分 30 个 SWE-bench dev 案例（pydicom 10 + sqlfluff 10 + astroid 6 + marshmallow 4），覆盖 4 个轻依赖仓库。pvlib/pvista 因重科学计算依赖栈超出评测环境约束而被排除并披露。两组对照方法（devorbit 多阶段 vs single-agent 单 prompt）各 30 runs，使用同一模型 deepseek-v4-flash-0731、同一机器门禁、同一 token 预算。

devorbit 组管道跑通 20/30（completed），single-agent 组 15/30。closedLoop 0%（模型编码能力限制，非管道问题），安全合规 100%。所有失败（环境安装不兼容 Python 3.13、JSON 输出过长解析失败、baseline 绿排除）按协议诚实披露。这不是官方 SWE-bench 排行榜分数。

早期 pilot（`sqlfluff__sqlfluff-884`）仍作为单案例调优链保留，证明来源冻结、环境构建、缺陷复现、gold 隔离和证据校验链路。

## 环境与复现

可审计环境为 Ubuntu 22.04、Python 3.10.12、SQLFluff 0.4.1、pytest 6.2.5、packaging 21.3，其余版本见 `evaluation/public-pilot/sqlfluff__sqlfluff-884/requirements.lock`。SQLFluff 0.4.1 分类器只列到 Python 3.9，因此 Python 3.10.12 是已披露偏差；它已在两个干净依赖目录中复现完全相同的业务断言，不是导入、安装或 collection 失败。

离线核验仓库证据：

```bash
npm run validate-public-pilot
```

联网下载固定源码、核验 archive/LICENSE 摘要、重建依赖并复现 baseline：

```bash
npm run reproduce-public-pilot
```

重放脚本只访问 base 源码和公开 test patch，不读取 gold patch。正式多方法评测仍须扩充到预注册的 repository-grouped validation/test 集，冻结 Agent 配置后才运行 test，并按 Wilson、paired bootstrap 和 McNemar 协议报告。

## 真实本地模型调优链

模型固定为本地 Ollama `qwen3:8b`，digest `500a1f06...b8b41`，temperature 0、seed 847。运行器只读取冻结 issue/comments、base 源码摘录、测试失败和已披露前序反馈；禁止读取 PR 页面、expected fix、gold patch、gold digest、gold 日志和 SWE-bench model patch 字段。确定性机器门禁拥有最终授权，接受公式固定为：

```text
machineGatePassed && modelAccept
```

| Run | 结果 | 机器证据 |
|---|---|---|
| 1 | 补丁契约前阻断 | 模型生成的 unified diff 元数据不可信 |
| 2 | 拒绝 | 只改注释；目标与回归失败 |
| 3 | 拒绝 | 全局修改 `BaseSegment.is_whitespace`；普通 code token 被误标 |
| 4 | 拒绝 | 首轮只修普通 whitespace；次轮精确替换契约不匹配 |
| 5 | 拒绝 | ANSI whitespace/newline 配置使简单分类通过，但多行注释内部 newline 仍失败 |
| 6 | 拒绝 | 两次重复 Run 5 补丁；目标失败、回归 144/145 |
| 7 | 旧门禁通过 | policy-guided 写路径限制到 `raw.py`；目标 1/1、回归 145/145、简单分类与两项策略门禁全绿；后续源码审计发现 name/type 与重复关键字残余 |
| 8 | 控制失败 | 增加工厂兼容性探针；两轮模型响应超时，零补丁汇总又暴露 artifact 缺失处理问题；原始报告和 transcript 保留 |
| 9 | 拒绝 | 冻结 600 秒响应上限并修复零补丁汇总；两轮 `oldText` 来自错误文件，契约拒绝，未执行测试 |
| 10 | 拒绝 | 返工看到原始被拒提案；首轮路径越界，次轮虽声明 `raw.py` 仍复制 ANSI tuple，契约拒绝 |
| 11 | **增强门禁拒绝** | 模型锚定 `newclass = type` 工厂块并实际执行补丁；目标、145 项回归、普通分类和四项工厂兼容探针均失败；路径与 BaseSegment 不变量保持，机器门禁和 verifier 拒绝 |

Run 7 按其冻结标准确实通过，但不是最终有效性结论。Run 11 是增强门禁终态，manifest SHA-256 为 `cd82100d...7d4a44`；报告与 transcript 绑定全部前序摘要、本轮补丁和日志，失败证据离线校验 39/39：

```bash
npm run validate-public-model-pilot-v11
```

这条链没有得到可用于外推的模型成功结果。其价值是展示 DevOrbit 如何保存失败、把测试反馈转成机器策略、限制返工范围、发现旧门禁漏检，并在更强证据出现后推翻先前接受。它不是独立泛化、模型能力分数或正式 benchmark。

## 跨仓独立单次验证

模型运行前，系统只根据数据来源、许可、固定源码可获得性、FAIL_TO_PASS 数量、依赖规模和基线可复现性筛选候选；没有读取候选的 gold 实现补丁，也没有按模型结果换题。四个候选及淘汰原因固化在 `candidate-selection.json`，最终选择与 SQLFluff 不同仓库的 `pydicom__pydicom-965`。

| 字段 | 冻结值 / 结果 |
|---|---|
| 上游 | `pydicom/pydicom`，MIT，base `ee775c8...` |
| 源码归档 | SHA-256 `2530c36a...1e678` |
| 模型 / 参数 | 本地 `qwen3:8b`；digest `500a1f06...b8b41`；temperature 0；seed 847 |
| 基线 | 隐藏 FAIL_TO_PASS `1 failed`；同文件 `38 passed, 1 failed, 1 skipped` |
| 工作区隔离 | 模型源码副本不含隐藏 test patch 和分类探针；无网络工具；gold 实现不读取、不保存、不哈希 |
| 协作 | triage → RCA → patch；verify 因补丁契约预先拒绝而未启动 |
| 尝试预算 | 1 次；无测试反馈、无返工、不得换题 |
| 终态 | 两条模型 exact-edit 完全重复；第一条仅写入一次性模型工作区，第二条匹配 0 次；评估副本创建前 fail closed |
| 测试结论 | 补丁后目标、回归和分类均未运行；不得声称通过 |
| 离线校验 | 26/26；正式 benchmark 仍为 `not_run / 0 cases` |

冻结 manifest SHA-256 为 `14284812...642d4a`，运行器 SHA-256 为 `503382f8...07dff0`。运行器还保留了一次模型调用前的摘要格式预检失败，证明正式运行前 Agent 调用数为 0。正式运行耗时约 258 秒，三个模型角色输出均绑定模型 digest 和输入/输出摘要。

```bash
npm run validate-independent-model-pilot
```

审计发现 v1 exact-edit 执行器在完整校验两条编辑前，先修改了临时模型工作区。它没有创建评估副本或执行隐藏测试，但原子性不足已在 `contract-rejection.json` 披露。新增 `exact-edit-transaction` 先在内存中规划全部编辑，任一失败不暴露输出，重复编辑与路径越界回归 3/3。该改进不用于重跑或美化已经冻结的 pydicom 结果。

独立结果必须按失败计入：它证明系统能在新仓库上阻断不可应用补丁，也暴露本地 8B 模型与 v1 事务实现的局限；它不证明修复成功率、独立泛化能力或排名优势。
