# 场景迁移复制路径（结算支付域 → 库存域）

V1.0.0 新增第二类场景迁移证据：在**不改动状态机、Worker 边界、Skill、门禁、证据链与审批机制**的前提下，将 DevOrbit 从结算支付域（checkout-service：支付转圈 + 重复下单）复制到库存域（inventory-service：秒杀超卖 + 台账负库存），完整闭环一次跑通。

运行与复核：

```bash
npm run scenario-migration   # 生成 reports/scenario-migration.{json,md}
npm test                     # src/fixture-migration.test.js 3 个迁移断言
```

## 一、迁移结论

| 口径 | 结算域（原场景） | 库存域（迁移场景） |
|---|---|---|
| 事故形态 | 连接池缩容 + 幂等重试放大，重复下单 | 乐观锁条件被移除，并发扣减超卖、台账负库存 |
| 基线测试 | 3 失败 / 1 通过 | 3 失败 / 1 通过 |
| 补丁后 | 4 通过 / 0 失败 | 4 通过 / 0 失败 |
| 发布决策 | promoted（10% 灰度健康） | promoted（10% 灰度健康） |
| 终态 | learned（知识沉淀） | learned（知识沉淀，service=inventory-service） |
| RAG 命中 | EP-001 | EP-007（库存域历史超卖事故） |
| 证据链 | 校验通过 | 校验通过 |

机制一致性断言（自动测试）：两场景的 **Worker×Skill 调用序列完全相同**、**状态机转移路径完全相同**（received→triaged→diagnosed→planned→verified→canary→confirmed→learned）、**MCP 工具集完全相同**。

## 二、保持不变的机制（复制时零改动）

1. **状态机**：`config/case-lifecycle.yaml` 的转移表、补证回边、返工回边与熔断策略。
2. **Worker 边界**：7 个职能 Worker（intake/impact/rca/patch/verify/release/learning）+ Manager 委派，职责与交接关系不变。
3. **Skill 体系**：7 个版本化 Skill（SignalFusion/ImpactMap/EvidenceRCA/PatchPlan/TestGate/ReleaseGuard/KnowledgeCard），trace 记录 skillVersion + skillDigest。
4. **门禁与审批**：RCA 置信度 ≥0.80、测试零失败、回滚点就绪、L2 HMAC 签名审批、灰度 SLO 违约回滚。
5. **证据链**：摄入→影响→RCA→补丁→测试→审批→灰度→知识的链式 sha256 校验。
6. **知识机制**：Episode 多维硬过滤（租户→服务→环境→git/config 版本）+ 负面方案召回 + 准入生命周期。
7. **幂等与隔离**：case_id+action 幂等键、隔离工作区、终态销毁。

## 四、迁移步骤（复制到其他业务域的操作清单）

1. **建 fixture**：编写目标域最小服务 + 失败测试（基线必须真实失败），以及 surface/deep 分层信号。
2. **声明 profile**：在 `src/fixture-profiles.js` 增加目标域条目（服务拓扑、影响面、根因候选、修复模板、发布版本）。
3. **补知识**：在 `knowledge/episodes.json` 增加目标域 Episode，硬过滤字段与 profile 对齐；历史教训写入 `negativeLessons`。
4. **跑闭环**：`runPipeline({ fixture: '<domain>' })` 或 `POST /api/runs {"fixture":"<domain>"}`，按业务断言验收。
5. **验收口径**：基线失败数、补丁后通过数、发布决策、终态、证据链校验、机制序列一致性。

## 五、适用边界与诚实声明

- 库存域案例与结算域案例同为**团队构造的脱敏仿真**，用于证明机制复制路径，不代表真实生产库存系统的收益。
- 迁移证据只覆盖确定性无密钥路径；真实模型/真实平台接入时的迁移成本（提示词、工具凭据、CI 环境）需在接入后另行评估。
- Profile 中的修复模板是确定性演示实现；生产场景由模型生成补丁，profile 仅提供上下文与门禁。
