## 项目名称

DevOrbit——多 Agent 软件研发闭环引擎

## 作品简介（500 字以内）

线上缺陷分散在 Issue、日志、反馈、代码仓和流水线中，研发人员需手工对齐事实，再跨测试、审批、灰度和复盘接力。DevOrbit 面向研发与平台团队，基于 AgentTeams Manager–Worker 协作，把“发现→定位→修复→验证→发布→沉淀”编排为可回放闭环。

系统由信号归并、影响分析、根因诊断、补丁、验证、发布、学习 7 个 Agent 协作，能力封装为 7 个自定义 Skill，并锁定 1 个官方日志查询 Skill；10 个 Tool 经 MCP 2025-06-18 接入。Case State 传递上下文，OTLP Trace 串联证据。服务端强制 Agent×Tool 最小权限、签名审批、Schema、幂等与回滚。

差异化是证据驱动：根因绑定现场与历史引用，补丁在隔离仓完成 Red→Green，发布由灰度指标确认。7 个闭环、4 个检索和 6 个对抗安全案例全通过；7 组对照/消融显示关闭核心门禁后安全与决策准确率下降。成果将开放 Skill、MCP Server、策略契约和评测集。

## 可选补充说明

当前 V0.4 是无外部密钥、无云资源依赖的确定性工程 Demo。7 个独立 Worker 通过版本化 Case State 与结构化任务消息协同；Issue、观测、仓库、CI、发布和知识库六类适配器均经 MCP 2025-06-18 `tools/call` 接入。本地 Fixture/Mock 仅替代外部平台，补丁与测试在隔离样例仓中真实执行。完整成功路径有 15 次工具审计，支持同 Case/Trace 审批续跑、低置信停止、测试失败阻断和灰度退化自动回滚；新增 Agent×Tool 策略、签名审批、运行时 Schema、OTLP 导出和对照/对抗评测。官方日志查询 Skill v0.0.2 已锁定到 Intake/RCA Worker；仅在显式配置最小只读权限后启用，当前未调用云账号。
