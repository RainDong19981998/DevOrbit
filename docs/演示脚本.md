# 3 分钟演示脚本

## 0:00–0:25 痛点与输入

“一个线上缺陷通常不是一个 Issue，而是用户反馈、接口错误、日志、指标和变更记录的碎片。DevOrbit 让七个不同职能 Agent 从这些碎片开始，完成修复发布和知识沉淀，而且每一步都有证据。”

点击“运行完整案例”，指出左侧 5 类信号和顶部 7 阶段。

录制视频可直接打开 `http://127.0.0.1:4173/?demo=happy-path`，页面会用真实 API 自动跑完正常案例并自动执行一次审批续跑；现场答辩仍建议手动点击审批按钮。

## 0:25–1:20 诊断与修复

观察协同轨迹，强调 Manager 把同一 Case State 分发给 Worker。根因面板出现后说明：

“系统没有只给一句可能是 Redis，而是把配置变更、连接池超时日志和错误率抬升绑定到同一时间窗，首因置信度 91%；同时给出受影响服务、接口和代码文件。Patch Agent 只生成最小变更和显式回滚点。”

## 1:20–2:10 测试与安全门禁

“Patch Worker 复制带缺陷样例仓，先运行同一批测试复现 3 个失败，再修改两个文件；Verify Worker 现场复跑，4 项全部通过，形成 Red→Green 输出摘要制品。该动作被评为 L2，运行在同一个 Case/Trace 上暂停。”此时点击“批准 10% 灰度”，再说明：“批准后从原状态继续；若错误率增加超过 1% 或 p95 增加 20%，策略引擎自动回滚。”

指向审批号、灰度前后错误率和“可回滚”。

## 2:10–2:40 证据与知识沉淀

“放量不是终点。Learning Agent 把 Case、根因、补丁、测试、审批、灰度指标合成知识卡，并生成三条预防措施。下次类似缺陷可以检索复用。统一 Run ID 支持对整个链路回放审计。”

## 2:40–3:00 工程价值

滚动到 Skill 资产区和底部 MCP/OTLP/评测指标：

“Agent 负责判断和协作，七个自定义 Skill 封装稳定能力，官方日志查询 Skill 的可审计快照锁定给 Intake 和 RCA。十个 Tool 经 MCP 2025-06-18 调用，完整路径有十五条工具审计和二十九个 OTLP Span。服务端策略独立校验权限、签名审批与 Schema。GitHub、Git、Jenkins 和 Argo 原生连接器 8/8，含 Git 的 hardened runner 6/6；Argo 定点 JSON Patch 并绑定 observedGeneration，完成结果可跨重启重放，未知结果 fail closed 并带 Provider 证据对账。一个 SWE-bench dev pilot 已真实复现失败，但正式公开分数仍为零。”

## 评委高频问答

**这是规则引擎还是 Agent？** 当前初赛 Demo 用确定性 Worker 运行器确保人人可复现，同时实现与 AgentTeams v1.2.2 对齐的 Team Leader–Worker 分工、共享状态、Skill 调用和异常门禁。真实模型推理是可替换的诊断/编码能力，不承担确定性安全控制；复赛部署到官方 AgentTeams runtime。

**AgentTeams 体现在哪里？** 锁定官方 v1.2.2 commit `849182a`：使用 `agentteams.io/v1beta1` 的 1 个 Team Leader + 7 个 Worker，Team Room 承载可观察协作，MCP Server 由 Worker spec 声明，自定义 Skill 与锁定的官方日志查询 Skill 随 Worker ZIP 分发。`validate-agentteams` 完成 140/140 项资源/包/Skill 契约检查；替身 CLI 冒烟验证“7 个 ZIP 上传→资源覆盖→Team 查询”。这是本地契约与编排证据，当前 Demo 未伪装成已启动官方集群或调用云账号。

**MCP 是真的还是接口图？** `/mcp` 是符合 2025-06-18 基本 Streamable HTTP 约束的 JSON-RPC 端点，支持初始化、绑定 Worker 身份的会话、工具发现/调用、输入输出 Schema、结构化结果、Origin/版本校验和会话销毁。服务端 Agent×Tool allowlist 和签名审批不信任 Worker 自报结论。`npm run mcp-smoke` 独立验证协议与攻击分支；完整成功路径包含 15 条工具审计。

**安全是不是 Prompt 里写一句“不要发布”？** 不是。Manager 在 RCA、测试和回滚门禁通过后签发带 Case、Action、过期时间的 HMAC 回执，Release Worker 只能消费，不能自行签发；MCP 服务端再次验签。6/6 对抗案例覆盖越权、伪造、过期、跨 Case 重放和 Schema 混淆。生产身份认证仍需由 Higress/mTLS/OIDC 提供，本地 Header 只做会话绑定。

**100% 指标可信吗？** 它只表示 7 个确定性仿真回归案例全部符合预期，并给出 95% Wilson 区间，不代表生产准确率。7 组对照/消融显示关闭证据、测试、审批或灰度门禁后指标降至 71.4%–85.7%；朴素单体基线为 28.6%。当前已冻结并复现 1 个 SWE-bench dev validation pilot，用来验证评测 harness，不计 DevOrbit 分数；复赛扩到 30 个公开仓缺陷并引入人工/单 Agent 对照。

**RAG 是否只是固定答案？** 知识库含 4 条团队构造案例，检索使用可复现的词法/标签评分并返回 Top-3、得分和稳定引用。Golden Cases 的 Top-1 均命中预期历史案例，但这只验证当前仿真集；复赛增加公开缺陷集和 embedding 混合检索。

**如何证明根因不是编的？** 每个候选都必须携带 evidence refs；低于 0.8 或证据冲突时停止自动修复，转为补证或人工。Golden Cases 评测 Top-3 命中率。

**为什么比编码 Agent 更有价值？** 编码只是中间一步。DevOrbit 覆盖信息归并、影响面、验证、发布结果确认和组织知识沉淀，并把高风险动作纳入审批与回滚。

**当前指标是真实生产数据吗？** 不是；7 个闭环指标来自团队构造仿真。SWE-bench pilot 的 baseline 失败是真实公开缺陷，但尚未运行 DevOrbit，因此也不是效果分数。正式效果只会在冻结的多案例 test split 上报告。
