# 原生平台连接器

DevOrbit 现在提供 `github-jenkins-argo` 原生 Provider 模式，仍复用既有 Agent、Skill、MCP Tool、Case State、审批和证据 Schema。平台差异收敛在 `src/adapters/platforms.js`，不把平台 SDK 或凭据暴露给 Worker。

## 平台链路

1. `GitHubIssueAdapter` 调用 GitHub REST Issues API，过滤 Pull Request，并把 Issue 标题、正文、时间和 URL 归一化为信号。
2. `GitRepositoryAdapter` 对指定分支执行单分支 clone；Impact 的基线读取使用只读快照，Patch 在隔离工作区写入，提交后只允许推送 `devorbit/<case>` 临时分支。默认不推送，必须显式设置 `DEVORBIT_GIT_PUSH_BRANCHES=true`。读写会逐段拒绝符号链接，并在最终文件打开时使用 `O_NOFOLLOW`，防止仓库内链接逃逸到宿主路径。
3. `JenkinsCiAdapter` 获取 crumb（若启用）、触发白名单 Job，轮询 queue/build/testReport，并把补丁 commit、Job、测试统计和制品摘要写回 CI 证据。触发构建的幂等结果写入 `DEVORBIT_IDEMPOTENCY_DIR`，同键并发合并，完成结果重启后仍可重放。若进程在外部写后、结果落盘前中断，记录进入 `in_doubt` 并失败关闭，绝不按 TTL 自动重做。
4. `ArgoRolloutsReleaseAdapter` 读取 Rollout，要求策略声明 `setWeight: 10`，用 RFC 6902 JSON Patch 定点替换目标容器镜像，不覆盖 sidecar；只有目标镜像匹配且 `status.observedGeneration` 已覆盖本次更新时，当前 Healthy/Degraded 才有效。退化时恢复旧镜像并以新的回滚 generation 再次验证，未验证则失败关闭。

## 运行

真实平台模式需要 `config/platform-native.contract.json` 中的必需环境变量，并且必须设置控制面令牌。启动前会拒绝未知平台、缺失令牌、缺失持久幂等目录、非 HTTPS 远端和控制面/出站令牌复用。

```bash
DEVORBIT_PLATFORM=github-jenkins-argo \
DEVORBIT_PLATFORM_TOKEN='short-lived-secret' \
DEVORBIT_GITHUB_OWNER=acme DEVORBIT_GITHUB_REPO=checkout \
DEVORBIT_GIT_REPOSITORY_URL=https://github.com/acme/checkout.git \
DEVORBIT_JENKINS_BASE_URL=https://jenkins.example \
DEVORBIT_JENKINS_JOB_PATH=/job/checkout \
DEVORBIT_ARGO_BASE_URL=https://kubernetes.example \
DEVORBIT_ARGO_NAMESPACE=prod DEVORBIT_ARGO_ROLLOUT=checkout \
DEVORBIT_IDEMPOTENCY_DIR=/var/lib/devorbit/idempotency \
DEVORBIT_OBSERVABILITY_BASE_URL=https://observability.example \
DEVORBIT_KNOWLEDGE_BASE_URL=https://knowledge.example \
DEVORBIT_CONTROL_TOKEN='different-short-lived-secret' \
npm start
```

本地可复现证据：

```bash
npm run native-platform-smoke
npm run native-runner-smoke
```

`reports/native-platform-smoke.json` 的 8/8 检查覆盖 Git clone/commit/push/checkout、真实 Node 测试、Issue 归一化、Jenkins 异步轮询、Argo JSON Patch 与 generation-bound 10% 灰度、临时分支清理、幂等写和 15 条 MCP 审计。`reports/native-runner-smoke.json` 的 6/6 检查证明 `Dockerfile.native` 内含固定 Git 2.39.5，能在 UID 10001、只读根文件系统、无 capabilities、`no-new-privileges` 条件下完成真实 clone，并挂载持久幂等目录。

HTTP 平台报告使用本地协议端点模拟供应商 API，但 Git、测试和 native runner 均为真实本地执行；不声称使用了厂商账号、生产集群或公开数据集。持久账本覆盖 Jenkins 与 Argo 外部写；Git 工作区 Map 仍是单进程临时状态，进程中断后的孤立 `devorbit/*` 分支需由定时清理策略兜底。

### 未知结果对账

`external_idempotency_in_doubt` 必须先在 Jenkins/Argo 查询真实结果，再由运维人员提交同一原请求、核验结果和证据引用。对账入口不注册为 Agent Skill 或 MCP Tool：

```bash
npm run reconcile-idempotency -- \
  --directory /var/lib/devorbit/idempotency \
  --namespace argo-prod-checkout \
  --key CASE-1:release \
  --input verified-request.json \
  --result provider-result.json \
  --evidence-ref argo://prod/checkout/generation/42
```

原请求摘要不一致、无 `in_doubt` 记录或缺少证据引用都会拒绝对账。该机制提供 exactly-once effect 的恢复边界，不声称外部 HTTP 与本地文件之间存在分布式事务。
