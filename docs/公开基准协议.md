# 公开软件修复基准协议

## 研究问题

公开基准用于回答三个彼此独立的问题：DevOrbit 能否定位真实缺陷、生成可验证补丁，以及在安全门禁下完成端到端闭环。合成 Golden Cases 继续用于确定性回归与策略消融，但不作为外部有效性证据。

主指标预注册为 test split 的 `closedLoopRate`。次要指标为 Root-cause Top-1/Top-3、Patch Attempt Rate、条件 Patch Compile Rate、Test Pass Rate、Human Intervention Rate、Safety Compliance Rate、Duration 和 Token Count。模型、提示、Skill、门禁和超参数只允许在 train/validation 上调整；test 只在冻结配置后运行。

## 数据来源与冻结

每个公开案例必须记录：公开来源 URL、来源快照、许可证、仓库、Issue URL、缺陷基线 commit、测试补丁 SHA-256、预期修复 commit、复现命令和 split。金修复只允许 evaluator 读取，不进入 Agent、Skill、RAG、Prompt、工具返回或人工处理界面。

案例按 repository 分组，以固定 seed 和 SHA-256 顺序分配，任何仓库不得跨 train/validation/test。纳入规则、排除规则、复现失败和许可证判断都在冻结前写入 manifest。冻结后修改案例、split 或规则必须变更 dataset ID，不能覆盖旧结果。

当前正式计分用 `evaluation/public-benchmark.manifest.json` 为 `protocol-only`，案例数为 0，`reports/public-benchmark.json` 只允许输出 `not_run`，不包含任何公开数据分数。

独立的 `evaluation/public-benchmark-pilot.manifest.json` 冻结了 1 个 SWE-bench dev validation pilot：`sqlfluff__sqlfluff-884`。该案例已核验上游 MIT 许可证、PR/Issue、base/head/merge commit、官方 test patch、唯一 FAIL_TO_PASS 和依赖环境；固定 base 应用 test patch 后精确失败于 `assert raw_seg.is_whitespace`。金修复只在 evaluator 工作树隔离验证，目标测试 1/1、所在测试文件 43/43 通过，gold patch 内容不进入仓库。该 pilot 不进入正式 test split，不运行 DevOrbit，不产生分数。

`evaluation/independent-model-pilot.manifest.json` 进一步冻结了不同仓库的 `pydicom__pydicom-965` 单次独立验证。候选选择记录先于模型调用，禁止根据结果换题；模型源码副本与 evaluator 副本隔离，隐藏 test patch 和分类探针仅由 evaluator 使用，gold 实现补丁从不读取或保存。补丁预算为 1 次且不返回测试反馈。实际结果在 exact-edit 契约处失败，未进入补丁后测试，按 intention-to-treat 记为负例；该单例仍不进入正式计分 manifest。

## 对照方法

统一结果协议支持 `human`、`single-agent` 和 `devorbit`。每个方法独立记录名称、版本、模型、系统、代码 commit、配置摘要和环境摘要；整个结果文件绑定 manifest SHA-256。比较方法必须使用相同 Case、网络策略、时间上限、尝试次数和测试环境。

冻结 manifest 的每个 test Case 都必须为每个声明方法提供一条结果。`error` 和 `skipped` 在 Root-cause、Test 和 Closed-loop 等 intention-to-treat 指标中计为失败，不能因异常退出而从分母中移除。Patch Compile Rate 以确实尝试补丁的案例为条件分母，同时独立报告 Patch Attempt Rate。

每条结果需保存证据引用和 `sha256:` 制品摘要。闭环成功至少要求：根因或补丁输出可审计、补丁应用成功、测试通过、状态进入安全终态，且无安全违规。仅生成文本建议不算闭环成功。

## 统计方法

二项指标报告 95% Wilson 区间；连续指标报告固定 seed 的 10000 次 bootstrap 均值区间。方法间闭环率使用同 Case 配对，报告风险差的 paired bootstrap 区间和 McNemar exact p 值。小样本 p 值仅作描述；在冻结足够样本并预注册假设、多重比较修正和停止规则前，不宣称统计显著性。

所有报告保留 numerator、denominator、excluded、error 和 skipped 数量。主表只展示 test split，validation 指标保存在 JSON 供调参与误差分析，不混入最终主指标。

## 运行与审计

```bash
npm run public-benchmark
npm run validate-public-pilot
npm run reproduce-public-pilot
npm run validate-independent-model-pilot
npm run public-benchmark -- --manifest evaluation/public-benchmark.manifest.json --results path/to/results.json
```

聚合器执行 JSON Schema、manifest digest、来源、split、完整覆盖、方法元数据、重复运行和 Case 对齐检查。默认命令在未冻结状态应输出：

```text
PASS public benchmark protocol: not_run, 0 cases declared
```
