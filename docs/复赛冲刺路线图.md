# DevOrbit 复赛与决赛冲刺路线图

目标不是继续扩充工具数量，而是在 V0.7.0 已完成官方 AgentTeams 本地运行的基础上，接入厂商账号研发工具链，并以正式公开基准证明外部有效性。

## 晋级后 10 天交付节奏

| 时间 | 工程交付 | 评测与证据 | 晋级价值 |
|---|---|---|---|
| D1 | 将本地 AgentTeams 运行配置整理为全新环境部署脚本 | 保存官方命令、资源状态、Room 截图和 Trace | 把已验证本机运行升级为可移植部署 |
| D2–D3 | GitHub/GitLab Repo + Issue MCP Adapter | 权限矩阵、Webhook 重放、幂等和错误注入 | 证明平台可替换性与真实数据接入 |
| D4 | 真实 CI Adapter；容器沙箱和命令白名单 | 公开仓 Red→Green 制品、资源限制、超时/逃逸测试 | 提升工程可信度与安全边界 |
| D5 | Kubernetes/Argo Rollouts 或等价灰度 Adapter | 审批回执、10% 灰度、SLO 阈值、自动回滚录像 | 形成真实端到端闭环核心 Demo |
| D6 | OTLP Collector 接 AgentScope Studio/LoongSuite | Agent/Tool/RAG/Model Trace 与线上指标看板 | 证明 Production 可观测性 |
| D7–D8 | 30 个公开缺陷案例集；真实模型诊断/补丁插件 | 人工、单 Agent、DevOrbit 三组；bootstrap/Wilson 区间 | 从确定性回归升级为外部有效性证据 |
| D9 | Prompt/RAG 注入、越权、故障注入与恢复演练 | 威胁矩阵、攻击成功率、MTTR、回滚正确率 | 回答企业评委最关心的可靠性问题 |
| D10 | 冻结 V0.8、录制 3 分钟 Demo、进行答辩压力测试 | 全新环境一键部署、摘要、SBOM、最终审计 | 降低现场失败与口径漂移风险 |

## 公开评测设计

### 数据集

- 30 个来自 Apache-2.0/MIT 公开仓库、可重放且有已知修复提交的缺陷。
- 至少覆盖 JavaScript/TypeScript、Python、Java/Go 三类栈；按定位、修复、安全分支分层抽样。
- 冻结任务输入和预期补丁后再运行模型，防止根据结果反向设计案例。

### 对照组

1. 人工 Runbook：由熟悉仓库的工程师执行并记录时长。
2. 单 Agent：同模型、同 Token/工具预算，不启用角色分工和独立门禁。
3. DevOrbit：同模型预算，启用 AgentTeams、Skill、策略门禁、RAG 和证据链。

### 主要指标

- Top-3 根因文件命中率、Patch 构建/测试通过率、端到端闭环成功率。
- 不安全动作阻断率、误发布率、回滚正确率、人工介入率。
- P50/P95 时延、模型 Token/成本、MCP 调用数、证据覆盖率。
- 报告分母、失败样本、95% 区间和原始 JSON；不只展示平均数或成功案例。

## 决赛现场主线

主 Demo 只演示一个高密度案例：真实 Issue/日志进入 → AgentTeams Room 协作 → 真实仓库补丁 → CI Red→Green → 人工签名审批 → Kubernetes 10% 灰度 → 指标健康确认或一键注入退化 → 确定性回滚 → OTLP 回放与知识卡写回。

备用 Demo 使用当前 V0.7.0 无密钥确定性路径，断网、无云资源时仍能证明协议、策略和失败分支。现场不依赖临时安装，不展示未经演练的功能。

## 必须保持的诚实边界

- 当前只声称官方 AgentTeams 本地实跑；云账号、云 Skill、真实厂商 Git/CI/发布和生产集群只有产生可复核运行证据后才能写“已接入”。
- 仿真指标与公开仓指标分开报告；业务收益必须来自真实用户研究或部署数据。
- 本地 Header 绑定不是生产认证；生产使用网关 mTLS/OIDC、短期凭据和外部审计存储。
- 任何真实模型接入都补充模型版本、Prompt、温度、预算、重复次数与失败样本。
